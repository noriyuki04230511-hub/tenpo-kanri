# tenpo-kanri（株式会社3k 店舗管理システム）

各卓のiPadを起点に、出勤・受付・ヒアリング・接客・成約後の手続き・アンケート・予約を記録する店舗運営アプリ。
既存システム（ALL Mobile）とは独立したシステムで、既存システムとは一切つながない（2026-11-17 決定）。店舗・スタッフの名簿はこのシステム自身が持ち、シフトは持たない。

## いまの状態（2026-11-17・工程B）

- `public/index.html` … アプリ本体（見本店だけで動く試作）。画面は表を直接読まず、データベースの入口の関数（`app_` で始まる9本）だけを呼ぶ
- `supabase/migrations/` … 新しいデータベース（Supabase: tenpo-kanri）の定義。表27枚（全て権限設定あり・画面側からの直接の読み書きは不可）と入口の関数
- `tests/e2e_local.py` … 手元の試験用データベースで、受付からアンケートまで・予約・通信が切れたときの再送を通しで確認する試験
- `prototype/index.html` … データベースにつなぐ前の画面試作 v0.5（見本データだけで動く）
- `docs/existing-system-readonly-window.sql` … 既存システム側にいったん作り、独立の決定で取り消した読み取り用の窓の記録
- `vercel.json` … 公開先の設定（`public/` をそのまま配信。検索に載せない）

`public/index.html` にある `sb_publishable_…` は公開用の鍵で、画面に置く前提のもの。これだけでは表を読めない。

## 決まりごと

- お客様の氏名・電話番号・生年月日を持たない。
- 鍵やパスワードをこの置き場に入れない。
- 既存システム（selectsim-system）には接続しない。
- 設計書・決定記録は Claude のプロジェクト「店舗管理アプリ制作」が正本。
